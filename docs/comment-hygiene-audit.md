# 注释与文档的叙述清理：可复核的判定口径

这份文件说明仓库里"哪一类文字算迁移叙述、哪一类不算"，以及用什么扫。

## 一、判为叙述（已清除）

| 形态 | 例子 | 为什么算叙述 |
| --- | --- | --- |
| 批次编号 | `B933`、`B1241` | 指"这是第几步做的"，与对象本身无关 |
| 相对批次 | `this batch`、`earlier batch`、`last batch`、`next batch` | 同上，且换个读者就失去指代 |
| 中文相对批次 | `这一批`、`本批`、`上一批`、`下一批` | 同上 |
| `Batch N` / `batch N` | `batch 266 picked up the old value` | 同上 |
| `第 N 批` | `第 87 批` | 同上 |
| 第一人称过程 | `我第一版`、`我又`、`我当时` | 描述"我怎么试错的"，不是"这东西是什么" |
| `迁移（…）` / `迁移了` | `迁移（B1370）` | 描述搬运动作而非结果 |
| `本会话` / `本批次` | `本会话第五次` | 会话坐标，读者无从复核 |
| `phase N`（迁移阶段） | `deferred to Phase 3` | 同批次编号 |
| `as of Batch N` | `as of Batch 265` | 同上 |

## 二、判为技术语境（保留）

| 形态 | 例子 | 为什么保留 |
| --- | --- | --- |
| `batch` 作业务概念 | `BatchDispatchPolicy`、`CapacityBatchDurationTests`、批量求解 | 这是被建模的对象本身 |
| `第一步`/`三步`/`前两步` | "本函数第一步就是调用它" | 描述算法步骤，不是迁移步骤 |
| `P9 Batch NNN：` | 判据自己在描述被删文档的标题格式 | 描述格式，不是叙述 |
| `曾经`/`原先` | "这里曾经硬编码成 B737" | **描述对象的历史状态与缺陷**，是技术事实 |
| 十六进制常量 | `0x94D049BB133111EBUL` | 不是批次号（曾误报一次） |
| 测试数据字符串 | `new AircraftRegisterNumber("B1234")` | 是数据，不是注释 |

## 三、扫描方式

```bash
python scripts/audit-comment-hygiene.py
```

脚本对 `.cs` 只统计注释行（`//`、`///`），对 `.md` 统计全文；命中数必须为 **0**。

## 四、这条口径的边界

**它只覆盖上表第一节列出的形态。** 一种新的叙述写法（例如"第三轮复核时"）不会被它发现——
所以这份清单本身就是判据的一部分：**新增一类叙述写法时，要同时把它加进脚本与这张表。**
